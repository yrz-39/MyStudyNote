## 实验目的
1. 掌握基础流水线 CPU 的设计方法。
2. 掌握基础流水线 CPU 中阻塞检测和旁路转发的实现方法。
3. 掌握基础流水线 CPU 分支静态预测实现方法。
4. 掌握基础流水线 CPU 程序代码优化的编程方法。

#### 1.1 转发部件
##### 原理图和电路图

###### 原理图
转发检测一般在执行 **EX 段** 生成转发信号。

当 EX 段检测到以下条件同时满足时，需要生成转发选择信号：

- 源寄存器号与 **M 段** 或 **WB 段** 的目的寄存器号相同；
- 目的寄存器不是 `0` 号寄存器；
- 指令类型为运算类指令，即 `RegWr = 1`。

对于 **BusA 转发检测信号 `BusAFW`**，其选择规则如下：

- `BusAFW = 00`：选择寄存器堆输出 `BusA`，无须转发；
- `BusAFW = 01`：转发来自 EX/M 流水段寄存器的运算结果 `M.Result`；
- `BusAFW = 10`：转发来自 WB 段 `MemtoReg` 选择器的结果 `WB.BusW`。

`BusAFW` 的逻辑表达式可根据上述判断条件生成。

对于 **BusB 转发检测信号 `BusBFW`**，判断方法与 `BusAFW` 类似。

需要注意转发数据的优先级：当 `M.rd` 与 `WB.rd` 都和 EX 段源寄存器号相同时，距离当前指令更近的数据优先级更高，因此 **M 段数据优先于 WB 段数据**。

#### 1.2 阻塞部件
##### 原理图和电路图

###### 原理图
阻塞检测在 **ID 段** 执行，主要用于解决 **load-use 数据冒险**。

当检测到以下情况时，需要暂停流水线一个时钟周期：

- 前序指令是 `load` 类型指令；
- 当前指令的源寄存器地址与前序指令的目的寄存器地址相同。

其中，`load` 类型指令可通过控制信号 `MemtoReg` 判断：

- `MemtoReg = 1`：表示前序指令需要从数据存储器读取数据，即为 `load` 指令；
- `MemtoReg = 0`：表示前序指令不是 `load` 指令。

当前指令是否包含源寄存器，需要根据指令类型判断：

- `R`、`I`、`S`、`B` 型指令包含源寄存器 `rs1`；
- `R`、`S`、`B` 型指令包含源寄存器 `rs2`；
- 指令类型可通过 `opcode` 进行识别。

当阻塞信号有效时，流水线控制方式如下：

- `PC` 写使能无效；
- `IF/ID` 流水段寄存器写使能无效；
- `ID` 段控制器输出信号清零；
- 当前指令在 `ID` 段暂停一个时钟周期。

#### 1.3 跳转部件
##### 原理图和电路图

###### 原理图
跳转检测与单周期 CPU 设计中的跳转控制器模块类似，用于判断分支预测是否正确，并决定是否更新 `PC`。

该模块的主要输入信号包括：

- `EX.BandJ`：分支或跳转控制信号；
- `EX.Result[0]`：运算结果最低位，用于部分跳转判断；
- `EX.Zero`：零标志信号，用于分支条件判断。

输出信号为 `PCsrc`，且高电平有效：

- `PCsrc = 0`：预测正确，继续顺序执行；
- `PCsrc = 1`：预测失败，需要跳转到目标地址继续执行。

本实验在 **M 段** 进行分支跳转检测。当预测失败时，需要冲刷前面流水段中已经错误读取的指令信息，包括：

- `IF` 段；
- `ID` 段；
- `EX` 段。

因此流水线相当于插入三条空指令 `NOP`。在 RISC-V 中，常用空指令为：

```text
addi zero, zero, 0
```

其对应机器码为：

```text
0x00000013
```

#### 1.4 流水段寄存器部件
##### 原理图和电路图

###### 原理图
流水段寄存器用于在相邻流水段之间传递数据和控制信号，是流水线 CPU 中连接各级流水段的重要时序部件。

流水段寄存器中需要保存的信息主要包括：

- 当前流水段需要传递到下一流水段的数据；
- 当前流水段产生的控制信号；
- 与时序控制相关的信号。

作为时序电路，流水段寄存器还需要包含以下控制信号：

- `CLK`：时钟信号；
- `CLR`：清零信号；
- `WE`：写使能信号。

根据本实验的时序设计，流水段寄存器在 **时钟下降沿** 写入数据。

写使能信号 `WE` 的控制规则如下：

- 当阻塞信号有效时，`WE` 无效，流水段寄存器保持原值；
- 当中止执行信号 `Halt` 有效时，`WE` 无效，流水线暂停执行；
- 当冲刷信号有效时，需要清空流水段寄存器中的错误指令信息。

需要注意的是，Logisim 中寄存器的清零通常是 **异步清零**，直接使用异步清零可能会因为线路毛刺导致错误。因此，本实验中流水段寄存器采用 **同步清零** 的方式实现：

- 当清零信号 `CLR` 有效时，将输入数据置为 `0`；
- 再通过写入寄存器的方式完成清零；
- 因此 `CLR` 有效时，`WE` 也必须有效。

#### 1.5 EU部件
##### 原理图和电路图

###### 原理图
在执行阶段（**EX 段**）中，执行部件 `EU` 需要同时完成以下两类功能：

- 算术逻辑运算；
- 分支或跳转目标地址计算。

算术逻辑运算部分与单周期 CPU 中的 `ALU` 设计基本一致。`ALU` 的两个操作数分别由选择信号控制。

操作数 A 的选择由 `ALUASrc` 控制：

- 选择 `PC`；
- 选择 `BusA`。

操作数 B 的选择由 `ALUBSrc` 控制：

- 选择 `BusB`；
- 选择常量 `4`；
- 选择立即数。

`ALU` 的运算类型由 `ALUctr` 信号决定。运算完成后：

- 通过 `Result` 输出运算结果；
- 产生零标志位 `Zero`，用于后续分支判断。

分支或跳转目标地址计算部分由一个 **32 位加法器** 实现。

该加法器的操作数选择如下：

- 操作数 A：由 `BandJ` 信号控制，可选择 `PC` 或 `BusA`；
- 操作数 B：选择立即数。

加法器输出 `PCTarget`，用于表示分支或跳转指令的目标地址。

#### 1.6 整体拼接
##### 原理图和电路图

###### 原理图
整体拼接部分用于将前面设计的各个模块连接成完整的五级流水线 CPU。除了基本的数据通路和控制通路外，还需要加入复位、断点调试和周期计数等辅助功能。

为了保证 CPU 每次重启时都能从相同的初始状态开始执行程序，需要设计复位信号 `Reset`。

`Reset` 的主要作用包括：

- 初始化 CPU 中各个部件的控制信号；
- 清空数据存储器；
- 设置 `PC` 寄存器的起始地址 `Init Addr`。

为了便于跟踪和调试流水线执行过程，设计中加入断点调试功能，相关信号包括：

- `BP.PC`：断点地址；
- `BP.EN`：断点使能信号。

当 `BP.EN` 有效，且当前 `PC` 与断点地址 `BP.PC` 相等时，CPU 暂停流水线执行。此时可以观察各流水段中指令的执行状态，便于调试流水线中的数据冒险、控制冒险和转发逻辑。

为了验证程序执行所需的周期数，设计中还加入了 **时钟周期计数器**，用于记录程序从开始执行到结束时经历的总时钟周期数。

### 思考题
1. **转发检测模块中，没有根据操作码 OP 来判断当前指令是否操作 rs1 和 rs2 字段，可能对输出产生什么影响？会导致程序执行错误吗？如何解决该问题，是否必要？被阻塞的指令能产生有效转发信号吗？**
	- 可能产生错误的转发信号，比如`lui`、`auipc`、`jal` 等指令本身不需要读取 `rs1` 或 `rs2`，可能产生错误的转发判断
	- 不一定会有错误，即使产生了转发信号，只要后续 ALU、立即数选择器、写回控制等逻辑没有真正使用这个操作数，错误的转发值就不会影响最终结果。
	- 但是会产生一些不算执行错误的问题,比如转发次数统计错误，解决方法是在转发模块中添加是否使用`rs1`和`rs2`的字段，如果只是想跑通CPU测试的话，不是一定必要
	- 被阻塞的指令一般**不能产生有效转发信号**。因为阻塞时，该指令还没有真正进入 EX 阶段执行，它只是停留在 IF/ID 或 ID 阶段等待。
2. **本实验中将跳转检测放在 EX 段执行，能否继续优化迁移到 ID 段执行？试分析可行性。**
	- 可以迁移到 ID 阶段，但需要增加 ID 阶段的比较器、目标地址计算器、转发通路和阻塞判断逻辑。对于本实验的基础流水线 CPU 来说，放在 EX 阶段更简单稳定；如果追求更高性能，可以进一步优化到 ID 阶段。

3. **如何修改流水线 CPU 的设计，实现非法指令和结果溢出两种异常处理，标识异常类型，跳转异常处理程序**
	- 非法指令通常在 ID 阶段检测。控制器译码时，如果发现 OP、funct3、funct7 的组合不属于当前 CPU 支持的指令，就产生非法指令异常信号
	- 结果溢出一般在 EX 阶段检测，主要针对有符号加减法，ALU 可以额外输出一个 `Overflow` 信号，当当前指令需要检测溢出时，产生异常
	- 增加一些简单的异常寄存器进行异常信息保存，并对异常情况进行简单编码
	- 发生异常时，CPU 应该
		1. 保存异常指令的 PC 到 EPC；
		2. 保存异常类型到 Cause；
		3. 禁止异常指令继续写寄存器或写存储器；
		4. 冲刷异常指令之后的错误指令；
		5. PC 跳转到异常处理程序入口地址；
		6. 异常处理程序根据 Cause 判断异常类型并处理。
4. **在实验中对于分支指令采用静态预测的方法来解决控制冒险，讨论如何实现 1 位动态预测的方法。**
	- 可以增加一个分支历史表 BHT(上次跳转=1，没跳转=0)
	- 在IF阶段查表根据一位动态预测规则进行预测
	- 在EX阶段完成实际地址跳转，并与预测值进行比较，若不一致则要flush
	- 用实际跳转结果根据一位动态预测更新预测方式进行更新BHT
5. **简述高级流水线设计方法。**
	高级流水线设计的目标是在保证程序正确执行的前提下，进一步提高指令吞吐率，降低平均 CPI，减少数据冒险、控制冒险和结构冒险带来的性能损失。常见设计方法包括：
	1. **加深流水线级数**：将原有流水段进一步细分，使每一级完成的组合逻辑更少，从而提高时钟频率。但流水线级数越深，分支预测失败或异常处理时需要冲刷的指令也越多，因此需要配合更好的冒险处理机制。
	2. **改进数据冒险处理**：通过更完善的旁路转发通路、阻塞检测逻辑和寄存器相关性判断，减少因为数据相关导致的停顿。例如将 EX、MEM、WB 等阶段的结果尽早转发给后续指令使用。
	3. **优化控制冒险处理**：采用更准确的分支预测方法，如动态分支预测、分支历史表 BHT、分支目标缓冲 BTB 等，提前预测下一条指令地址，减少分支跳转带来的流水线冲刷损失。
	4. **采用多发射或超标量结构**：在一个时钟周期内同时取出、译码并执行多条指令，通过多个功能部件并行执行，提高指令级并行度。
	5. **支持乱序执行和顺序提交**：允许后续无相关性的指令先执行，避免某条指令等待数据或功能部件时阻塞整个流水线；同时通过重排序缓冲区等结构保证最终提交结果仍然符合程序原有顺序。
	6. **进行寄存器重命名**：通过增加物理寄存器，消除写后写和写后读等伪相关，提高乱序执行时的并行度。
	7. **优化存储系统访问**：通过指令 Cache、数据 Cache、访存缓冲和乱序访存等方式减少访存延迟，降低 load/store 指令对流水线的影响。
