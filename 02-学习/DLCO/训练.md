# 多周期CPU设计 — 训练册

> **定位**：这不是“考前背模板”的题单，而是更适合**前期刷题、练推理、练独立作答能力**的训练册。  
> **建议搭配**：先看 [[多周期CPU设计复习]] 建立框架，再用本册做能力训练，最后再用 [[多周期CPU设计_习题集]] 做考前回顾。

---

## 使用方法

### 训练原则

1. **先做后看**：每题先独立写出答案，再展开提示/答案。
2. **写理由，不只写结论**：例如不只写“下一状态是 S8”，还要写“因为当前指令是 `lw`，在 S1 后需要进入 Load 执行态”。
3. **限时训练**：
   - 小题：2~4 分钟/题
   - RTL题：5~8 分钟/题
   - 综合题：10~20 分钟/题
4. **错题复盘**：做完后记录自己错在“概念混淆 / 状态不熟 / 控制信号不熟 / 计算粗心 / 不会变式”。

### 记号约定

本训练册默认沿用 [[多周期CPU设计复习]] 中的记号：
- 状态：`S0~S9`
- 中间寄存器：`IR / MAR / MDR / ALUout / A / B / CC`
- 寄存器名采用 `xN`
- 如果老师课堂上使用 MIPS 记号（如 `rt/rd`），请自行对照理解

### 建议刷题顺序

- 第1轮：只做 **第一部分~第三部分**
- 第2轮：加入 **第四部分~第五部分**
- 第3轮：限时完成 **第六部分综合题**

## 第一部分：基础识别训练

> 目标：先把“这条指令走几拍、经过哪些状态、哪些寄存器在用”练熟。

### 1.1 指令类型与状态序列

写出下列指令的**指令类型、周期数、状态序列**：

1. `add x5, x6, x7`
2. `ori x8, x9, 15`
3. `lui x10, 0x12345`
4. `lw x11, 20(x12)`
5. `sw x13, 24(x14)`
6. `beq x1, x2, offset`
7. `jal x1, target`

<details>
<summary>提示</summary>

先不要背题，直接从 [[多周期CPU设计复习#4.9 各指令周期数汇总]] 回忆：
- R/I/U 通常 4 周期
- `lw` 最长 5 周期
- `sw` 4 周期
- `beq/jal` 3 周期
</details>

<details>
<summary>答案</summary>

1. `add x5, x6, x7`：R-type，4周期，`S0→S1→S4→S5→S0`
2. `ori x8, x9, 15`：I-type，4周期，`S0→S1→S3→S5→S0`
3. `lui x10, 0x12345`：U-type，4周期，`S0→S1→S3→S5→S0`
4. `lw x11, 20(x12)`：Load，5周期，`S0→S1→S8→S9→S0`
5. `sw x13, 24(x14)`：Store，4周期，`S0→S1→S6→S7→S0`
6. `beq x1, x2, offset`：Branch，3周期，`S0→S1→分支执行态→S0`
7. `jal x1, target`：Jump，3周期，`S0→S1→S2→S0`
</details>

### 1.2 状态识别快问快答

回答下列问题：

1. 哪个状态负责**取指令**？
2. 哪个状态负责**译码并读取寄存器**？
3. 哪个状态负责 **R-type 执行**？
4. 哪个状态负责 **Load 访存读数**？
5. 哪个状态负责 **Store 真正写内存**？
6. 哪个状态负责 **Jump 完成并写回返回地址**？

<details>
<summary>答案</summary>

1. `S0`
2. `S1`
3. `S4`
4. `S8`
5. `S7`
6. `S2`
</details>

### 1.3 哪些寄存器里已经有值？

若 CPU 当前处于以下状态，写出“**此时哪些中间结果一定已经准备好**”：

1. 进入 `S1` 之后
2. 进入 `S4` 之前（执行的是 R-type）
3. 进入 `S8` 之前（执行的是 `lw`）
4. 进入 `S9` 之前（执行的是 `lw`）
5. 进入 `S7` 之前（执行的是 `sw`）

<details>
<summary>参考答案</summary>

1. 进入 `S1` 后：`IR` 已经有当前指令，`PC` 已经更新为 `PC+4`
2. 进入 `S4` 前：`A`、`B` 已读出，R-type 已译码完成
3. 进入 `S8` 前：`MAR` 中已有有效访存地址
4. 进入 `S9` 前：`MDR` 中已有从内存读出的数据
5. 进入 `S7` 前：`MAR` 中已有地址，`MDR` 中已有待写入内存的数据
</details>

---

### 1.4 判断题：说明理由

判断对错，并简要说明理由：

1. 多周期 CPU 的所有指令 CPI 都相同。  
2. 多周期 CPU 的时钟周期由最慢指令决定。  
3. `lw` 通常是多周期 CPU 中周期数最多的基础指令。  
4. `S5` 一定是“把 ALUout 写回寄存器堆”的状态。  
5. `beq` 不跳转时，最终 PC 仍然是顺序下一条地址。  

<details>
<summary>答案</summary>

1. 错。不同指令所经过的状态数不同。
2. 错。多周期的时钟周期由**最慢微步骤**决定。
3. 对。基础设计里 `lw` 一般最久。
4. 大体上对。在本套状态定义中，`S5` 是 R/I/U 类的写回态，通常把 `ALUout` 写回寄存器。
5. 对。因为 `S0` 中 PC 已加 4，不跳转时保持顺序执行。
</details>

## 第二部分：控制信号与状态推理训练

> 目标：从“背状态”提升到“能根据状态动作反推控制信号”。

### 2.1 填空：S0（IFetch）

在 `S0` 中，需要完成：
- `IR ← M[PC]`
- `PC ← PC + 4`

请填写下列控制信号：

- `PCWr =`
- `IRWr =`
- `PCout =`
- `Add1MUX =`
- `Add2MUX =`
- `ALUctr =`

<details>
<summary>答案</summary>

- `PCWr = 1`
- `IRWr = 1`
- `PCout = 1`
- `Add1MUX = 0`（选 PC）
- `Add2MUX = 1`（选常数 4）
- `ALUctr = add`
</details>

---

### 2.2 比较题：S6 与 S7

比较 `sw` 的 `S6` 和 `S7`：

1. `S6` 做什么？
2. `S7` 做什么？
3. 为什么 `MemWr` 不在 `S6` 置 1，而在 `S7` 置 1？

<details>
<summary>答案</summary>

1. `S6`：`MDR ← B`，先把待写数据暂存起来。
2. `S7`：`M[MAR] ← MDR`，真正完成内存写操作。
3. 因为 `S6` 先准备数据，`S7` 再用 `MAR` 和 `MDR` 完成写内存。多周期设计把“准备数据”和“真正访存”拆开了。
</details>

---

### 2.3 比较题：S8 与 S9

比较 `lw` 的 `S8` 和 `S9`：

1. `S8` 的核心 RTL 是什么？
2. `S9` 的核心 RTL 是什么？
3. 这两个状态中谁会让 `RegWr=1`？谁会让 `MDRWr=1`？

<details>
<summary>答案</summary>

1. `S8`：`MDR ← M[MAR]`
2. `S9`：`R[rd] ← MDR`（或课堂若用 MIPS 记号则为写回目标寄存器）
3. `S9` 让 `RegWr=1`；`S8` 让 `MDRWr=1`
</details>

---

### 2.4 反推状态

已知某状态满足：
- `RegWr = 1`
- `RegMUX = 0`
- 写回数据来自 `MDR`

问：最可能是哪个状态？对应哪类指令？

<details>
<summary>答案</summary>

最可能是 `S9`，对应 `lw` 的写回状态。因为只有 `lw` 会把内存读出的 `MDR` 写回寄存器堆。
</details>

---

### 2.5 反推指令类型

某条指令执行轨迹为：

`S0 → S1 → S3 → S5 → S0`

问：它可能是哪几类指令？为什么？

<details>
<summary>答案</summary>

可能是 I-type（如 `ori`）或 U-type（如 `lui`）。因为这两类都走“执行态 `S3` + 写回态 `S5`”的路径。
</details>

---

### 2.6 为什么 S1 里会写 MAR？

在 [[多周期CPU设计复习]] 中，`S1` 会做类似 `MAR ← A + SEXT(imm)` 的预计算。请回答：

1. 这样设计的直接目的是什么？
2. 为什么即使不是访存指令，也可能在 `S1` 做这个动作？
3. 这种做法体现了多周期 CPU 的什么思想？

<details>
<summary>参考答案</summary>

1. 提前准备访存地址，给后续 `lw/sw` 使用。
2. 因为 `S1` 是共用状态，统一做一部分预处理可以减少后续控制复杂度；对非访存指令来说，结果可能“算了不用”。
3. 体现了**状态复用 / 硬件复用 / 用统一微操作简化控制器**的思想。
</details>

---

### 2.7 小综合：只看控制信号猜状态

根据下列线索，猜测状态：

1. `PCWr=1, IRWr=1`
2. `MARout=1, MDRWr=1, MemWr=0`
3. `MDRMUX=1, MDRWr=1`
4. `RegWr=1, RegMUX=1`
5. `PCWr=1, RegWr=1, Jump=1`

<details>
<summary>答案</summary>

1. `S0`
2. `S8`
3. `S6`
4. `S5`
5. `S2`
</details>

## 第三部分：RTL 微操作训练

> 目标：把“会认状态”升级到“能自己完整写执行过程”。

### 3.1 完整写出 `lw`

写出 `lw x8, 16(x9)` 在多周期 CPU 中每个状态的 RTL。

<details>
<summary>提示</summary>

按顺序想：取指 → 读寄存器并算地址 → 读内存 → 写回。
</details>

<details>
<summary>答案</summary>

```text
S0: IR ← M[PC]
    PC ← PC + 4

S1: A ← R[x9]
    B ← R[?]          // 若实现中仍读第二源寄存器，可视为无关
    MAR ← A + SEXT(16)

S8: MDR ← M[MAR]

S9: R[x8] ← MDR
```
</details>

---

### 3.2 完整写出 `sw`

写出 `sw x5, 8(x6)` 在多周期 CPU 中每个状态的 RTL。

<details>
<summary>答案</summary>

```text
S0: IR ← M[PC]
    PC ← PC + 4

S1: A ← R[x6]
    B ← R[x5]
    MAR ← A + SEXT(8)

S6: MDR ← B

S7: M[MAR] ← MDR
```
</details>

---

### 3.3 完整写出 `ori`

写出 `ori x3, x4, 12` 的 RTL。

<details>
<summary>答案</summary>

```text
S0: IR ← M[PC]
    PC ← PC + 4

S1: A ← R[x4]
    B ← R[?]
    MAR ← A + SEXT(12)    // 若沿用统一 S1 设计

S3: ALUout ← A or imm
    CC ← ALU flags

S5: R[x3] ← ALUout
```
</details>

---

### 3.4 完整写出 `jal`

写出 `jal x1, target` 的 RTL，并说明为什么写回寄存器的是当前 `PC` 而不是“旧 PC”。

<details>
<summary>答案</summary>

```text
S0: IR ← M[PC]
    PC ← PC + 4

S1: 指令译码，必要时读取寄存器

S2: R[x1] ← PC
    PC ← PC + SEXT(immJ)
```

原因：到达 `S2` 时，`S0` 已经把 `PC` 更新成 `PC+4`，所以此时写回 `R[x1]` 的正好是返回地址。
</details>

---

### 3.5 写出 `beq` 的 RTL，并解释不跳转时 PC 为什么不用“再 +4 一次”

<details>
<summary>参考答案</summary>

```text
S0: IR ← M[PC]
    PC ← PC + 4

S1: A ← R[rs1]
    B ← R[rs2]

S_Br: if (A == B)
          PC ← PC + SEXT(immB)
      else
          PC 保持当前值
```

原因：`S0` 中已经做过 `PC ← PC + 4`，所以不跳转时顺序下一条地址已经准备好了。
</details>

---

### 3.6 逆向题：从 RTL 猜指令

下面是一条指令的执行流程，判断最可能是哪类指令：

```text
S0: IR ← M[PC]; PC ← PC + 4
S1: A ← R[rs1]; B ← R[rs2]; MAR ← A + SEXT(imm)
S6: MDR ← B
S7: M[MAR] ← MDR
```

<details>
<summary>答案</summary>

`sw`。因为流程是“算地址 → 准备待写数据 → 写内存”。
</details>

### 3.7 逆向题：从状态轨迹猜指令

某条指令执行时经历：

`S0 → S1 → S8 → S9 → S0`

1. 它是哪类指令？
2. 哪一步真正访问了数据存储器？
3. 哪一步真正修改了寄存器堆？

<details>
<summary>答案</summary>

1. `lw`
2. `S8`
3. `S9`
</details>

## 第四部分：性能计算训练

> 目标：不要只会背“多周期更省面积”，要会自己算性能。

### 4.1 平均 CPI 计算

某多周期 CPU 指令混合比如下：

| 指令类型 | 比例 | CPI |
|---|---:|---:|
| R-type | 35% | 4 |
| I-type | 20% | 4 |
| lw | 20% | 5 |
| sw | 10% | 4 |
| beq | 10% | 3 |
| jal | 5% | 3 |

求平均 CPI。

<details>
<summary>答案</summary>

```text
CPIavg = 0.35×4 + 0.20×4 + 0.20×5 + 0.10×4 + 0.10×3 + 0.05×3
       = 1.40 + 0.80 + 1.00 + 0.40 + 0.30 + 0.15
       = 4.05
```
</details>

---

### 4.2 多周期时钟周期

假设最长的几个微步骤延迟分别为：

- IM访问：180ps
- RegFile读：90ps
- ALU计算：120ps
- DM访问：200ps
- 写寄存器开销（clk-to-Q + setup 合并考虑）：80ps

求多周期 CPU 的时钟周期。

<details>
<summary>答案</summary>

多周期时钟周期由**最慢微步骤**决定。  
最长是 `DM访问 200ps`。再加寄存器边界开销 `80ps`：

```text
Tmulti = 200 + 80 = 280ps
```
</details>

---

### 4.3 单周期 vs 多周期

设：
- 单周期临界路径 = 720ps
- 多周期时钟周期 = 240ps
- 多周期平均 CPI = 4.1

比较两者平均每条指令执行时间。

<details>
<summary>答案</summary>

- 单周期：`1 × 720 = 720ps/指令`
- 多周期：`4.1 × 240 = 984ps/指令`

所以多周期更慢：

```text
984 / 720 ≈ 1.37
```

即多周期平均每条指令时间约为单周期的 `1.37x`。
</details>

---

### 4.4 变式题：如果 `lw` 比例大幅上升

如果程序中 `lw` 的占比从 20% 增加到 45%，其他比例相应下降，你认为多周期 CPU 的平均 CPI 会如何变化？为什么？

<details>
<summary>参考答案</summary>

平均 CPI 会升高。因为 `lw` 是基础多周期设计中周期数最多的常见指令（通常 5 周期），其占比上升会显著拉高加权平均 CPI。
</details>

---

### 4.5 变式题：如果存储器速度大幅提升

若 IM 和 DM 的访问延迟显著缩短，你认为：

1. 单周期 CPU 会不会受益？
2. 多周期 CPU 会不会受益？
3. 谁更可能受益更明显？

<details>
<summary>参考答案</summary>

1. 会。
2. 也会。
3. 一般单周期受益更明显，因为单周期的临界路径往往强依赖 IM/DM 串联延迟；多周期虽然时钟周期也缩短，但它还受 CPI 较高影响。
</details>

## 第五部分：设计与变式训练

> 目标：从“会做题”走向“能改题、能应对变式”。

### 5.1 加一条新指令：`andi`

如果要在现有多周期 CPU 中增加 `andi rd, rs1, imm`：

1. 是否需要新增状态？
2. 它最可能复用哪个执行态？
3. 需要改的关键点是什么？

<details>
<summary>答案</summary>

1. 一般不需要新增状态。
2. 可复用 I-type 执行态 `S3` 和写回态 `S5`。
3. 主要修改 ALU 控制逻辑与立即数处理方式（按课程约定选择扩展方式，并让 ALU 执行 AND）。
</details>

---

### 5.2 加一条新指令：`bne`

若增加 `bne rs1, rs2, imm`：

1. 是否一定要新开一个状态？
2. 最核心的变化是“数据通路变了”还是“控制判定变了”？
3. 与 `beq` 的主要区别是什么？

<details>
<summary>参考答案</summary>

1. 不一定。若现有分支执行态足够，可复用。
2. 主要是**控制判定逻辑**变化，不一定要改主数据通路。
3. `beq` 是“相等则跳”，`bne` 是“不相等则跳”，本质区别在 Zero 条件的使用方式。
</details>

---

### 5.3 如果内存访问要两拍才能完成

假设数据存储器很慢，读/写都需要 2 个周期。请思考：

1. `lw` 的状态数会不会增加？
2. `sw` 的状态数会不会增加？
3. 最可能新增在哪一段？

<details>
<summary>参考答案</summary>

1. 会。
2. 大概率也会。
3. 会在原本的访存相关状态附近新增等待/完成状态。例如 `lw` 可能从 `S8→S9` 扩成 `S8→S8_wait→S9`；`sw` 也可能要在真正写内存前后加入额外状态。
</details>

---

### 5.4 如果想支持乘法 `mul`

假设 `mul rd, rs1, rs2` 需要 2 个执行周期，回答：

1. 最自然的扩展方法是什么？
2. 新状态更可能加在译码前、执行中，还是写回后？
3. 为什么？

<details>
<summary>答案</summary>

1. 在原有 R-type 执行路径上新增一个额外执行状态。
2. 更可能加在**执行中**。
3. 因为取指、译码、写回阶段并没有本质变化，变化的是运算本身需要更久，所以应该扩展执行阶段。
</details>

---

### 5.5 选择题：硬连线还是微程序？

对于下列场景，更倾向于哪种控制方式？说明理由。

1. 指令集规整、规模较小、追求速度
2. 指令很多、格式复杂、后续还想常改

<details>
<summary>答案</summary>

1. 硬连线控制：速度快、适合规整 RISC 风格
2. 微程序控制：更灵活、便于扩展和维护复杂指令系统
</details>

## 第六部分：综合训练题

> 目标：练“整题能力”，而不是一眼就知道该套哪条模板。

### 6.1 综合题A：从指令到控制流程

给定指令：`lw x8, 12(x9)`

请独立完成以下任务：

1. 写出完整状态序列
2. 写出每个状态的核心 RTL
3. 写出每个状态最关键的控制信号（不用穷举全部，只写最关键的 3~5 个）
4. 说明哪一步真正完成了：
   - 地址形成
   - 访问数据存储器
   - 寄存器写回

<details>
<summary>参考答案</summary>

**状态序列**  
`S0→S1→S8→S9→S0`

**RTL**
```text
S0: IR ← M[PC]
    PC ← PC + 4

S1: A ← R[x9]
    MAR ← A + SEXT(12)

S8: MDR ← M[MAR]

S9: R[x8] ← MDR
```

**关键控制信号示例**
- `S0`：`PCWr=1, IRWr=1, PCout=1, ALUctr=add`
- `S1`：`MARWr=1, Add1MUX=1, ALUctr=add`
- `S8`：`MARout=1, MDRWr=1, MemWr=0`
- `S9`：`RegWr=1, RegMUX=0`

**对应功能**
- 地址形成：`S1`
- 访问数据存储器：`S8`
- 寄存器写回：`S9`
</details>

### 6.2 综合题B：反向推理题

某条指令执行时，观察到以下现象：

- `S0` 后，`PC` 更新为 `PC+4`
- `S1` 后，`A=R[x3]`，`B=R[x4]`
- 下一状态中，ALU 执行 `sub`
- 之后没有发生 `RegWr`
- 最终回到 `S0`

请判断：

1. 最可能是哪类指令？
2. 该指令的目标功能是什么？
3. 哪个条件会影响最终 PC？

<details>
<summary>答案</summary>

1. 最可能是 `beq`
2. 比较两个寄存器是否相等，并根据结果决定是否分支
3. `A-B` 的比较结果（通常看 Zero 条件）
</details>

### 6.3 综合题C：自己画最小 FSM

只支持以下三类指令：
- `add`
- `lw`
- `sw`

请你自己设计一个“最小可用”的多周期 FSM，要求写出：

1. 需要哪些状态
2. 各状态大致做什么
3. 三类指令分别如何流动

> 这题**先自己画图**，不要直接翻答案。

<details>
<summary>参考答案（文字版）</summary>

一种自然设计：

- `S0`：IFetch
- `S1`：RFetch/ID
- `S4`：R-type Exec
- `S5`：R-type Writeback
- `S8`：Load memory read
- `S9`：Load writeback
- `S6`：Store prepare data
- `S7`：Store memory write

路径：
- `add`：`S0→S1→S4→S5→S0`
- `lw`：`S0→S1→S8→S9→S0`
- `sw`：`S0→S1→S6→S7→S0`
</details>

### 6.4 综合题D：异常插入点分析

假设你要在现有多周期 CPU 中加入“未定义指令异常”和“算术溢出异常”，请回答：

1. 未定义指令最可能在哪个状态检测？
2. 算术溢出最可能在哪个状态检测？
3. 为什么这两类异常不一定在同一个状态发现？
4. 异常发生后，控制器最少需要做哪三件事？

<details>
<summary>参考答案</summary>

1. 未定义指令：通常在 `S1` 译码时检测
2. 算术溢出：通常在 `S3/S4` 这类执行态检测
3. 因为前者是“看不懂指令编码”，后者是“指令能执行，但执行结果出错”，检测时机不同
4. 至少要做：
   - 保存异常指令位置（如 EPC）
   - 写入异常原因（Cause）
   - 把 PC 跳到异常处理入口
</details>
