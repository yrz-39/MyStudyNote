## 一、单周期CPU回顾（基础）

### 1.1 单周期CPU特点

| 特点 | 说明 |
|------|------|
| **CPI = 1** | 每条指令恰好 1 个时钟周期 |
| **时钟周期** | 取决于**最慢指令**（一般是 `lw`）的延迟 |
| **硬件** | 每个部件在每周期最多使用一次，大量闲置 |
| **优点** | 控制简单，状态少 |
| **缺点** | 周期长，资源利用率低 |

### 1.2 单周期数据通路组件

```
PC → IM → [IR] → RegFile → ALU → DM → RegFile
                     ↑              ↑
               立即数扩展 ← instr    MUX(数据来源)
```

**关键组件**：
- **PC**：程序计数器，存指令地址
- **IM**：指令存储器，32位地址 → 32位指令
- **RegFile**：32×32位寄存器堆，2读1写
- **ALU**：算术逻辑单元，支持 add/slt/sltu/or/srcB/sub
- **DM**：数据存储器，32位地址，32位数据
- **立即数扩展模块**：ExtOp 控制 immI/immU/immS/immB/immJ

### 1.3 控制信号总结

| 控制信号 | 宽度 | 作用 |
|---------|------|------|
| Branch | 1 | beq 时置 1，控制 PC 分支 MUX |
| Jump | 1 | jal 时置 1，控制 PC 跳转 MUX |
| ALUASrc | 1 | 0=rs1, 1=PC (J-type) |
| ALUBSrc | 2 | 00=rs2, 01=4 (PC+4), 10=imm |
| ALUctr | 4 | 选择 ALU 操作 (add/slt/sltu/or/srcB/sub) |
| MemtoReg | 1 | 0=ALUout, 1=DataMem (lw) |
| RegWr | 1 | 寄存器写使能 |
| MemWr | 1 | 数据存储器写使能 |
| ExtOp | 3 | 立即数扩展模式选择 |

### 1.4 单周期指令控制信号表

| 指令 | Branch | Jump | ALUASrc | ALUBSrc | ALUctr | MemtoReg | RegWr | MemWr | ExtOp |
|-----|--------|------|---------|---------|--------|----------|-------|-------|-------|
| **add** (R) | 0 | 0 | 0 | 00 | 0000 | 0 | 1 | 0 | × |
| **slt** (R) | 0 | 0 | 0 | 00 | 0010 | 0 | 1 | 0 | × |
| **sltu** (R) | 0 | 0 | 0 | 00 | 0011 | 0 | 1 | 0 | × |
| **ori** (I) | 0 | 0 | 0 | 10 | 0110 | 0 | 1 | 0 | 000(immI) |
| **lui** (U) | 0 | 0 | × | 10 | 1111 | 0 | 1 | 0 | 001(immU) |
| **lw** (I) | 0 | 0 | 0 | 10 | 0000 | 1 | 1 | 0 | 000(immI) |
| **sw** (S) | 0 | 0 | 0 | 10 | 0000 | × | 0 | 1 | 010(immS) |
| **beq** (B) | 1 | 0 | 0 | 00 | 1000 | × | 0 | 0 | 011(immB) |
| **jal** (J) | 0 | 1 | 1 | 01 | 0000 | 0 | 1 | 0 | 100(immJ) |

## 二、多周期CPU的设计动机

### 2.1 单周期的问题

```
lw 的延迟链:
  PC (clk-to-Q) → IM (access time) → RegFile (read) 
  → ALU → DM (access time) → RegFile (setup)

时钟周期 = T_clk-to-Q + T_IM + T_RegRead + T_ALU + T_DM + T_RegSetup + T_skew

最短指令(R-type)和最慢指令(lw)使用同一个时钟周期 → 浪费！
```

> 💡 **核心思路**：将指令执行拆成多个**微步骤(micro-steps)**，每个微步骤一个时钟周期，时钟周期由**最长的单步延迟**决定，而非整条指令延迟。

### 2.2 多周期CPU优势

| 方面 | 单周期 | 多周期 |
|------|--------|--------|
| 时钟周期 | 长（由最慢指令决定） | 短（由最长微步骤决定） |
| CPI | 1 | 3~5（不同指令不同） |
| 硬件复用 | 每个周期只用一次 | 同一部件多个步骤复用 |
| 面积 | 大（需独立加法器、ALU等） | 小（共享 ALU/加法器） |
| 灵活性 | 低 | 高（易扩展指令） |

### 2.3 关键权衡

```
多周期不一定更快！

例: 
  单周期 T_clk = 600ps，多周期 T_clk = 200ps
  指令混合: Load 22%, Store 11%, R-type 49%, Branch 16%, Jump 2%
  
  单周期: 1 × 600ps = 600ps/指令
  多周期: (22%×5 + 11%×4 + 49%×4 + 16%×3 + 2%×3) × 200ps
         = 3.94 × 200ps = 788ps/指令
  
  性能比 = 788/600 = 1.31x（多周期反而慢31%）
```

> 多周期真正的价值在于：**资源复用（更小面积）**和**设计灵活性**，而不是原始性能。

## 三、多周期数据通路（Datapath）

### 3.1 新增的微架构寄存器

| 寄存器 | 全称 | 位宽 | 作用 |
|-------|------|------|------|
| **IR** | Instruction Register | 32 | 保存当前指令 |
| **MAR** | Memory Address Register | 32 | 保存访存地址 |
| **MDR** | Memory Data Register | 32 | 保存访存数据（读/写） |
| **ALUout** | ALU Output Register | 32 | 保存 ALU 计算结果 |
| **CC** | Condition Code | 若干 | 保存 ALU 标志（如溢出OF） |

> **为什么需要这些寄存器？** 多周期中组合逻辑的输出需要在**寄存器中暂存**，供下一周期使用。否则流水会导致数据丢失。

### 3.2 数据通路结构示意

```
                     ┌─────────────┐
     PC ────────────→│     IM      │→ IR ──→ Control
       │             └─────────────┘
       │                  
       │    ┌──────────────────────┐
       │    │      RegFile         │
       │    │  A(rs1)  B(rs2)     │
       │    └──────┬──────┬───────┘
       │           │      │
       │     ┌─────┘      └─────┐
       │     │                  │
       │     ↓ [A]              ↓ [B]
       │   ┌─┴──────────────────┤
       │   │       ALU          │
       │   └────────┬───────────┘
       │            ↓ [ALUout]
       │     ┌──────┴───────┐
       │     │  DM / MAR    │
       │     └──────┬───────┘
       │            ↓ MDR
       │            │
       └────────────┘ (写回 RegFile 的 busW)
```

### 3.3 关键控制信号变化

| 信号 | 单周期 | 多周期 | 说明 |
|------|--------|--------|------|
| PCWr | 每周 | 特定状态 | 只在 IFetch 和 Jump 时写 |
| IRWr | 无 | IFetch | 只在取指令时写入 |
| MARWr | 无 | RFetch | 计算地址时写入 |
| MDRWr | 无 | lwExec/swExec | 访存时写入 |
| ALUoutWr | 无 | Exec | ALU 计算完写入 |
| RegWr | 组合 | 时序 | 只在写回阶段 |


## 四、指令的RTL微操作分解（核心）

### ⭐ RTL 符号约定

| 符号          | 含义              |     |               |     |        |
| ----------- | --------------- | --- | ------------- | --- | ------ |
| `R[r]`      | 寄存器 r 的值        |     |               |     |        |
| `M[addr]`   | 内存地址 addr 的值    |     |               |     |        |
| `PC`        | 程序计数器           |     |               |     |        |
| `M[PC]`     | 取指令（从 PC 指向的内存） |     |               |     |        |
| `SEXT[imm]` | 符号扩展立即数         |     |               |     |        |
| `ZEXT[imm]` | 零扩展立即数          |     |               |     |        |
| `←`         | 赋值              |     |               |     |        |
| `           |                 | `   | 拼接操作（如 `imm20 |     | 000H`） |

---

### 4.1 公共阶段

#### 🔷 阶段0：取指令 (IFetch) — 所有指令共用

**状态编码：0000**

```
RTL: 
  IR ← M[PC]       // 指令存储器读取
  PC ← PC + 4      // PC 自增（顺序执行预备）
  MAR ← PC + 4 ?   // 部分教材在这里提前计算下一地址
```

| 控制信号 | 值 | 说明 |
|---------|-----|------|
| PCout | 1 | PC 输出到地址总线 |
| IRWr | 1 | 写入 IR |
| PCWr | 1 | 写入 PC（PC+4） |
| Add1MUX | 0 | A 路选 PC |
| Add2MUX | 1 | B 路选立即数"4" |
| ALUctr | add | PC+4 |
| ALUoutWr | 0 | 不写 ALUout（直接写 PC） |
| 其余 | 0 | 写使能都关闭 |

> ⚠️ 取指令后，`PC` 已经指向 `PC+4`，后续分支/跳转可能需要修正 PC。

---

#### 🔷 阶段1：译码与取寄存器 (RFetch/ID) — 所有指令共用

**状态编码：0001**

```
RTL:
  A ← R[rs1]                    // 读取源寄存器1
  B ← R[rs2]                    // 读取源寄存器2
  MAR ← A + SEXT(imm)           // 预计算访存地址（仅对访存指令有用）
                                 // 对非访存指令：算完没用但不多花周期

  // 根据 opcode 决定下一状态（State 2~8）
```

| 控制信号 | 值 | 说明 |
|---------|-----|------|
| MARWr | 1 | 写入 MAR（提前算地址） |
| Add1MUX | 1 | A 路选 rs1 |
| Add2MUX | 0 | B 路选 0 |
| ExtOp | 1 | 符号扩展立即数 |
| ALUctr | add | rs1 + imm → 地址 |

> **⚠️ 考试常见坑**：`rs1` 的值是 `A`（已在状态1读取），但 MAR 计算用的 `A` 是**上一周期结束时写入**的，请画时序图时注意。

---

### 4.2 R-type 指令（add / slt / sltu）

**周期数：4** (IFetch → RFetch → RExec → RFinish)

#### 🔷 阶段2：执行 (RExec)

**状态编码：0100**

```
RTL:
  ALUout ← A op B      // op = add / slt / sltu
  CC ← ALU flags       // 记录溢出、符号、零标志
```

| 控制信号 | 值 |
|---------|-----|
| BMUX | 1（B 路选寄存器值） |
| ALUctr | add/slt/sltu |
| ALUoutWr | 1 |
| CCWr | 1 |

#### 🔷 阶段3：写回 (RFinish)

**状态编码：0101**

```
RTL:
  R[rd] ← ALUout      // 结果写回寄存器堆
```

| 控制信号 | 值 |
|---------|-----|
| RegMUX | 1（数据来源选 ALUout） |
| RegWr | 1 |
| 下一状态 | → IFetch (state 0000) |

---

### 4.3 I-type 指令（ori）

**周期数：4** (IFetch → RFetch → IExec → IFinish)

> ⚠️ **注意**：IExec 和 IFinish 的编码可能和 RExec/RFinish 不同，取决于设计

#### 🔷 阶段2：执行 (IExec)

**状态编码：0011**

```
RTL:
  ALUout ← A or SEXT(imm12)   // 立即数与寄存器值进行 or
  CC ← ALU flags
```

| 控制信号 | 值 |
|---------|-----|
| ExtOp | 000(immI) |
| BMUX | 0（B 路选立即数） |
| ALUctr | 0110 (or) |
| ALUoutWr | 1 |
| CCWr | 1 |

#### 🔷 阶段3：写回 (IFinish / 编码同 RFinish: 0101)

```
RTL:
  R[rd] ← ALUout
```

| 控制信号 | 值 |
|---------|-----|
| RegMUX | 1 |
| RegWr | 1 |

---

### 4.4 lui 指令 (U-type)

**周期数：4** (IFetch → RFetch → luiExec → luiFinish)

```
// 执行阶段
ALUout ← imm20 || 12'b0    // srcB 方式：ALU 选 B 路
  
// 写回阶段（同 RFinish/IFinish）
R[rd] ← ALUout
```

| 控制信号(Exec) | 值 |
|---------|-----|
| ExtOp | 001(immU) |
| ALUBSrc | 10 |
| ALUctr | 1111 (srcB) |
| ALUoutWr | 1 |

---

### 4.5 Load 指令（lw）— **最重要！最长**

**周期数：5** (IFetch → RFetch → lwExec → lwFinish)

#### 🔷 阶段2：计算地址 + 读内存 (lwExec)

**状态编码：1000**

```
RTL:
  MDR ← M[MAR]       // 从前面算好的 MAR 地址读内存
```

| 控制信号 | 值 | 说明 |
|---------|-----|------|
| MARout | 1 | MAR 地址送到地址总线 |
| MemWr | 0 | 读内存 |
| MDRMUX | 0 | MDR 写数据来自内存（非 B） |
| MDRWr | 1 | 写入 MDR |

> 📌 地址在 RFetch 阶段已经算好存在 MAR 中了，这里直接用。

#### 🔷 阶段3：写回 (lwFinish)

**状态编码：1001**

```
RTL:
  R[rt] ← MDR        // MDR 的内容写回寄存器
```

| 控制信号 | 值 |
|---------|-----|
| RegMUX | 0（数据来源选 MDR） |
| RegWr | 1 |

---

### 4.6 Store 指令（sw）

**周期数：4** (IFetch → RFetch → swExec → swFinish)

#### 🔷 阶段2：准备数据 (swExec)

**状态编码：0110**

```
RTL:
  MDR ← B             // B = R[rs2]，将待写数据存入 MDR
```

| 控制信号 | 值 |
|---------|-----|
| MDRMUX | 1（数据来源选 B 总线） |
| MDRWr | 1 |

#### 🔷 阶段3：写入内存 (swFinish)

**状态编码：0111**

```
RTL:
  M[MAR] ← MDR        // 将 MDR 写回内存
```

| 控制信号 | 值 |
|---------|-----|
| MARout | 1 |
| MemWr | 1（写内存） |

---

### 4.7 Branch 指令（beq）

**周期数：3** (IFetch → RFetch → beqExec → go to IFetch)

> Branch 在 RFetch 之后只需要一个执行周期就能决定下一跳转

**beq 执行阶段 (复用 RFetch 后的状态或额外状态)：**

```
RTL:
  // 在 RFetch 阶段已经读取了 A 和 B
  // ALU 计算 A - B
  if (Zero == 1) 
    PC ← PC + SEXT(immB)  // 注意：PC 已经在 IFetch 阶段加了 4
  else 
    PC ← PC + 4            // 不变，继续执行
```

| 控制信号 | 值 |
|---------|-----|
| ALUctr | 1000 (sub) |
| Branch | 1 |
| 下一状态 | IFetch |

> ⚠️ **关键理解**：beq 的 PC 计算是在 PC 已+4 的基础上进行的，因此 immB 的偏移是相对于 `PC+4` 的。但 RISC-V 中 immB 的编码已经考虑了这一点（imm[12:1] 左移 1 位）。

---

### 4.8 Jump 指令（jal）

**周期数：3** (IFetch → RFetch → JFinish)

#### 🔷 阶段2：跳转 (JFinish)

**状态编码：0010**

```
RTL:
  R[rd] ← PC             // 保存返回地址（当前 PC 已指向 PC+4）
  PC ← PC + SEXT(immJ)   // 跳转
```

| 控制信号 | 值 |
|---------|-----|
| ExtOp | 100 (immJ) |
| Add1MUX | 0 |
| Add2MUX | 0 |
| RegMUX | 0（PC+4 → Reg） |
| RegWr | 1 |
| PCWr | 1 |
| Jump | 1 |

---

### 4.9 各指令周期数汇总

| 指令类型 | 周期数 | 状态序列 |
|---------|-------|---------|
| **R-type** | **4** | 0→1→4→5→0 |
| **I-type (ori)** | **4** | 0→1→3→5→0 |
| **U-type (lui)** | **4** | 0→1→3→5→0 |
| **Load (lw)** | **5** | 0→1→8→9→0 |
| **Store (sw)** | **4** | 0→1→6→7→0 |
| **Branch (beq)** | **3** | 0→1→?→0（执行完状态决定） |
| **Jump (jal)** | **3** | 0→1→2→0 |

## 五、FSM有限状态机控制器（核心重点）

### 5.1 FSM 设计思路

```
有限状态机 = 组合逻辑（下一状态 + 输出）+ 时序逻辑（状态寄存器）
```

```
                  ┌──────────────────┐
  Opcode ────────→│                  │
                  │   控制逻辑(PLA)   ├──→ 控制信号(PCWr, RegWr, ...)
  当前状态 ───────→│   (组合逻辑)     ├──→ 下一状态(NextState)
                  └────────┬─────────┘
                           │
                     ┌─────┴──────┐
                     │  状态寄存器  │ ← Clk
                     └─────┬──────┘
                           │
                      当前状态 → (反馈回 PLA)
```

### 5.2 完整状态转移图

```
                    ┌─────────────────────────────────────────────────────────┐
                    │                                                         │
                    ↓                                                         │
                 ┌──────┐   (无条件)    ┌──────────┐                         │
                 │ S0   │─────────────→│   S1     │                         │
                 │IFetch│              │RFetch/ID │                         │
                 │ 0000 │              │  0001    │                         │
                 └──────┘              └────┬─────┘                         │
                    ↑                       │                               │
                    │          ┌────────────┼───────────┬───────────┐       │
                    │          │            │           │           │       │
                    │       op=000    op=000000  op=101011  op=100011 │     │
                    │     (jump)     (R-type)    (sw)       (lw)      │     │
                    │          │            │           │           │       │
                    │          ↓            ↓           ↓           ↓       │
                    │      ┌──────┐   ┌────────┐  ┌────────┐  ┌────────┐   │
                    │      │  S2 │   │  S4    │  │  S6    │  │  S8    │   │
                    │      │JFin │   │ RExec  │  │swExec │  │lwExec │   │
                    │      │ 0010│   │ 0100   │  │ 0110   │  │ 1000   │   │
                    │      └──────┘   └───┬────┘  └───┬────┘  └───┬────┘   │
                    │                     │           │           │         │
                    │                     ↓           ↓           ↓         │
                    │                 ┌───────┐  ┌────────┐  ┌────────┐     │
                    │   op=001101     │  S5   │  │  S7    │  │  S9    │     │
                    │    (ori) ──→  ┌┤RFinish│  │swFin  │  │lwFin  │     │
                    │               ││ 0101  │  │ 0111   │  │ 1001   │     │
                    │               │└───────┘  └────────┘  └────────┘     │
                    │               │       ↑           ↑          ↑       │
                    │               │       │           │          │       │
                    │               └───op=0110011(I型)─┘─所有完成都回到S0─┘
                    │                        (ori是I型)
                    │
                    └───────── 所有完成状态(S2,S5,S7,S9) ───────────┘
```

**状态编码：**

| 状态 | 编码 | 说明 |
|------|------|------|
| S0 (IFetch) | 0000 | 取指令 |
| S1 (RFetch/ID) | 0001 | 译码+取寄存器 |
| S2 (JFinish) | 0010 | Jump 完成 |
| S3 (IExec) | 0011 | I-type 执行 |
| S4 (RExec) | 0100 | R-type 执行 |
| S5 (RFinish/IFinish) | 0101 | R/I-type 写回 |
| S6 (swExec) | 0110 | Store 执行 |
| S7 (swFinish) | 0111 | Store 完成 |
| S8 (lwExec) | 1000 | Load 执行 |
| S9 (lwFinish) | 1001 | Load 完成 |

### 5.3 状态转移逻辑

```
S0 → S1:                       无条件 (always)
S1 → S2:                       当 opcode = 000010 (jump)
S1 → S3:                       当 opcode = 001101 (ori/其他I-type)
S1 → S4:                       当 opcode = 000000 (R-type)
S1 → S6:                       当 opcode = 101011 (sw)
S1 → S8:                       当 opcode = 100011 (lw)
S3 → S5:                       无条件 (IExec → IFinish)
S4 → S5:                       无条件 (RExec → RFinish)
S6 → S7:                       无条件 (swExec → swFinish)
S8 → S9:                       无条件 (lwExec → lwFinish)
S2 → S0:                       无条件 (JFinish → IFetch)
S5 → S0:                       无条件 (写回完成 → 取下一条)
S7 → S0:                       无条件 (sw完成 → 取下一条)
S9 → S0:                       无条件 (lw完成 → 取下一条)
```

**⚠️ 考试必考：在试卷上画出这个状态图，标出转移条件！**

### 5.4 下一状态逻辑方程（PLA实现）

用 `S[3:0]` 表示当前状态，`OP[5:0]` 表示 opcode，`NS[3:0]` 表示下一状态：

```
NS3 = S3·S2'·S1·S0'  (S8: lwExec → S9编码1001)
     + S3'·S2·S1·S0  (S9: lwFinish → S0 即 0000)

NS2 = S3'·S2'·S1'·S0  (S1: 且 OP=sw/jump → S6/JFinish)

NS1 = ...              (根据具体编码推逻辑表达式)
NS0 = ...
```

> 考试中通常要求**填写 PLA 真值表**或**推导下一状态布尔表达式**。

### 5.5 控制信号生成（PLA输出）

每个控制信号在各状态的值，见下一章 [[#六、完整控制信号表]]

```
PCWr = S0 + S2                            // IFetch 或 JFinish 时写 PC
IRWr = S0                                  // 仅在 IFetch 写 IR
RegWr = S5 + S9 + S2                       // 写回阶段
MemWr = S7                                 // 仅在 swFinish 写内存
```

## 七、硬连线 vs 微程序控制器

### 7.1 两种实现方式对比

| 特性 | 硬连线 (Hardwired) | 微程序 (Microprogrammed) |
|------|------------------|------------------------|
| **实现载体** | PLA（可编程逻辑阵列） | ROM（控制存储器 CS） |
| **下一状态** | 组合逻辑（逻辑方程） | 微PC + 派发ROM |
| **速度** | 快 | 慢（需要读 ROM） |
| **面积** | 小 | 大 |
| **灵活度** | 低（改指令需重设计 PLA） | 高（改 ROM 内容即可） |
| **设计复杂度** | 高（状态多时方程复杂） | 低（顺序编码） |
| **适合** | RISC（指令集小、规整） | CISC（指令集大、复杂） |
| **代表** | RV32I | IA-32 / x86 |

### 7.2 微程序控制器的结构

```
                     ┌─── 微PC (µPC) ───┐
                     │      计数器       │ ← 顺序 + 1
                     └────────┬─────────┘
                              │
                              ↓
                     ┌────────────────┐
     IR ──→ Dispatch ─→│  控制存储器(CS)  │ (ROM)
              ROM      │ (Microcode ROM) │
                       └────────┬────────┘
                                │
                         ┌──────┴──────┐
                         │   微指令寄存器   │
                         └──────┬──────┘
                    ┌───────────┼───────────┐
                    ↓           ↓           ↓
                控制信号1    控制信号2   下一微地址
```

### 7.3 微程序控制器的工作流程（9步）

```
1. 取微指令（从 CS 读取微指令到 µIR）
2. 指令译码（从 IR 获取 opcode）
3. 取寄存器操作数（A/B ← RegFile）
4. ALU 运算
5. 移位/逻辑操作
6. 访存（读/写数据存储器）
7. 寄存器写回
8. 微PC + 1（顺序执行下一条微指令）
9. 跳转（分支到特定微地址）
```

### 7.4 微指令格式

```
┌─────────┬──────────┬──────────┐
│ 控制字段  │  下一地址   │  派发位   │
│  22位    │   8位     │   2位    │
│ (控制信号) │ (下一µPC)  │ (条件跳转)│
└─────────┴──────────┴──────────┘
```

- **控制字段**：直接对应每个控制信号（PCWr, RegWr, ...）
- **下一地址**：指定下一条微指令地址（用于无条件顺序）
- **派发位**：根据 opcode 或条件选择跳转目标

## 八、性能分析与计算

### 8.1 核心公式

```
CPU时间 = 指令数 × CPI × 时钟周期

平均CPI = Σ(CPIi × Fi)   其中 Fi = 指令类型i的比例
```

### 8.2 多周期下的时钟周期

```
时钟周期 = max(各步骤延迟)

典型各步骤延迟：
  1. PC (clk-to-Q) → ... → IM 读出
  2. RegFile 读
  3. ALU 计算
  4. DM 访问
  5. RegFile 写

最慢步骤通常是：IM访问 或 DM访问 或 ALU计算
```

### 8.3 单周期 vs 多周期性能计算步骤

```
Step 1: 确定各部件延迟
Step 2: 确定单周期临界路径 → T_single
Step 3: 确定多周期最长单步 → T_multi
Step 4: 确定各指令CPI（3/4/5）
Step 5: 计算平均CPI
Step 6: 计算 平均指令时间 = CPI × T
Step 7: 比较单/多周期性能
```

### 8.4 典型计算例题

**题目**：给定以下延迟和指令混合比，比较单周期和多周期性能

| 部件 | 延迟 |
|------|------|
| IM | 200ps |
| ALU | 100ps |
| DM | 200ps |
| RegFile(读+写) | 100ps |
| PC+4 加法器 | 50ps |
| MUX/控制逻辑 | 50ps |

| 指令类型 | 比例 | 多周期CPI |
|---------|------|----------|
| ALU(R/I/U) | 45% | 4 |
| lw | 25% | 5 |
| sw | 10% | 4 |
| beq | 15% | 3 |
| jal | 5% | 3 |

**求解**：

```
Step 1: 单周期 T_clk = ?

  lw路径: PC(clk-to-Q 50) → IM(200) → RegRead(50) → MUX(50)
          → ALU(100) → DM(200) → MUX(50) → RegSetup(50)
          = 50+200+50+50+100+200+50+50 = 750ps
          
  beq路径: PC(50) → IM(200) → RegRead(50) → ALU(100) → Zero MUX
          = 50+200+50+100 = 400ps
  
  T_single = 750ps（取最慢路径）

Step 2: 多周期 T_clk = ?

  各步骤最长 = max(IM, ALU, DM, Reg) = max(200, 100, 200, 100) = 200ps
  + 寄存器 clk-to-Q + setup ≈ 50+50 = 100ps
  
  T_multi = 200 + 50 + 50 = 300ps（含寄存器开销）

Step 3: 平均CPI

  CPI_avg = 45%×4 + 25%×5 + 10%×4 + 15%×3 + 5%×3
          = 1.80 + 1.25 + 0.40 + 0.45 + 0.15
          = 4.05

Step 4: 比较

  单周期: 1 × 750ps = 750ps/指令
  多周期: 4.05 × 300ps = 1215ps/指令
  
  多周期比单周期慢 1215/750 = 1.62x
```

> **结论**：多周期通过**增加CPI**换取了**更小的硬件面积**和**设计灵活性**。

### 8.5 MIPS 计算

```
MIPS = 指令数 / (执行时间 × 10^6)
     = 主频 / (CPI × 10^6)

例: 1GHz CPU, 平均CPI=4.0
    MIPS = 10^9 / (4.0 × 10^6) = 250 MIPS
```

## 九、异常与中断处理

### 9.1 异常类型

| 异常 | Cause 编码 | 说明 |
|------|-----------|------|
| 未定义指令 | Cause = 1 | 遇到无法识别的 opcode |
| 算术溢出 | Cause = 2 | ALU 运算结果溢出 |
| 外部中断 | Cause = × | I/O 设备请求 |

### 9.2 异常处理流程

```
1. 检测到异常（未定义指令或 ALU 溢出）
2. EPC ← PC - 4          // 保存异常指令地址（PC已+4，需修正）
3. Cause ← 原因编码       // 记录异常原因
4. PC ← 0x10000          // 跳转到异常处理程序入口
```

### 9.3 异常处理控制信号

```
// 未定义指令（在译码阶段检测到）
EPCWr   = 1        // 保存 PC-4
CauseWr = 1        // 写入 Cause=1
PCMUX   = 0        // 选异常入口地址
Add1MUX = 0        // PC+0
Add2MUX = 10       // 选 0x10000
PCWr    = 1

// 溢出（在 ALU 执行阶段 CC 检测到 OF=1）
EPCWr   = 1
CauseWr = 1        // Cause=2
PCMUX   = 0
Add1MUX = 0
Add2MUX = 10
PCWr    = 1
```

### 9.4 异常处理 FSM 扩展

```
S1 (RFetch) ──→ 如果 opcode 无法识别 ──→ S_Exception (新状态)
SExec ──────→ 如果 OF=1 (CC检测) ──→ S_Exception

S_Exception 状态:
  EPC ← PC-4
  Cause ← Cause_num
  PC ← 0x10000
  → S0 (IFetch)
```

### 题型7：单周期改多周期

> **题目**：说明从单周期 CPU 到多周期 CPU，数据通路需要增加哪些寄存器，为什么？

**答案要点**：
- IR：暂存指令供译码
- MAR：暂存访存地址
- MDR：暂存内存读写数据
- ALUout：暂存 ALU 计算结果
- CC：暂存 ALU 标志

> 原因：单周期中组合电路的结果在**一个周期内直接用**，多周期中需要在**不同时钟周期使用**，所以必须用寄存器锁存中间结果。
