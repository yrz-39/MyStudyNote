# 流水线CPU设计(最重要的还是单周期)
## 1.概述
核心思想是把CPU执行指令拆分成5个阶段:
取指令(IF)->译码/取操作数(ID)->执行操作(EX)->访存(M)->写回(WB)
- 关键:**让多条指令并行执行**,降低CPI至接近1(理想情况是1),也就是如果流水线有N个阶段,那么吞吐率最高能提高N倍
- RISC-V适合流水线的原因:
	1. 32位定长指令，PC每次+4即可
	2. 源寄存器(Rs)固定，所以ID阶段可以一边译码，一边从寄存器堆中读取Rs1,Rs2的值，不需要根据指令来找寄存器
	3. 访存指令固定只有Load/Store,可以让不同类型指令更容易对齐
## 2.流水段设计

| 阶段  | 名称      | 主要功能                        | 主要硬件                  |
| --- | ------- | --------------------------- | --------------------- |
| IF  | 取指      | 根据PC在指令存储器中取指令，<br>同时计算PC+4 | 指令存储器<br>加法器          |
| ID  | 译码/取操作数 | 指令译码，得到所有控制信号<br>读寄存器，立即数扩展 | 控制器<br>寄存器堆<br>立即数扩展器 |
| EX  | 执行      | 把数据送入ALU计算地址或者<br>分支目标地址    | ALU，加法器               |
| M   | 访存      | 读或写数据寄存器<br>也可能更新PC         | 数据存储器<br>分支控制逻辑       |
| WB  | 写回      | 将结果写回寄存器堆                   | 寄存器堆                  |
### 2.1指令对齐
1. Load指令: 五个阶段都有(对应多周期里的五个周期),所以以其为标准，其他所有指令都朝它对齐
2. R型和普通I型: 不用访存，只是寄存器之间的操作，所以少了M阶段，但是如果直接对齐的话会出现**资源竞争(两条指令同时要使用某个器件)**，所以在M阶段补上一个**空阶段NOP**
3. Store指令：无WB阶段，在该阶段补上空阶段NOP
4. Beq等分支指令：无WB阶段，在该阶段补上空阶段NOP
5. jal指令(==注意这里与多周期有点不同==)：既要跳转，也要把PC+4写入rd，所以五个阶段都有，不用上空
### 2.2流水段设计原则
1. 以最复杂指令为准：Load
2. 较简单指令少的阶段用空阶段补齐
3. 同一个功能部件在固定阶段使用，比如寄存器写口统一在WB(第五阶段)使用，防止资源冲突
4. 每条指令对同一功能部件最多使用一起，减少结构冲突

## 3.流水线数据通路设计
- ==关键：在单周期CPU组合逻辑之间加入流水段寄存器==,这也是流水线CPU设计和单周期相同点较多的原因
一共需要四组流水段寄存器:
```text
IF/ID -> ID/EX -> EX/M -> M/WB
```
- 作用：在每个时钟上升沿，把前一阶段输出保存下来，作为下一阶段输入(**这里保存的，既有控制信号，也有数据**)，防止控制信号错误控制阶段，数据传入错误
### 3.1 控制信号的流动
一条指令在ID阶段译码产生控制信号，但是这些控制信号并不是马上都要用:

| 控制信号类型                 | 使用阶段            | 需要保存多久    |
| ---------------------- | --------------- | --------- |
| ExtOp                  | ID阶段(确定立即数扩展方式) | 当前周期使用    |
| ALUASrc,ALUBSrc,ALUctr | EX阶段(控制ALU)     | 传到ID/EX使用 |
| MemWr,Branch           | M阶段             | 继续往后传     |
| MemtoReg,RegWr         | WB阶段            | 继续往后      |
- **所以控制信号保存的关键就是后面还需不需要用到，如果需要用到就需要继续保存**，像水一样流动，所以每条指令的控制信号在该指令执行期间不变,不需要多周期那样的有限状态机
