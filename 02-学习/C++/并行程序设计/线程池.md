# 线程池ThreadPool
## 1.导入
我们知道,在计算一些比较复杂庞大的数据的时候,一个线程一直跑(串行)速度比较慢,性能较低,但是我们如果能将这个任务拆成几个部分,每个线程做一个部分,最后再组合起来,就能大大减小时间复杂度,所以我们很自然地想到创建多个线程来完成任务;
```cpp
std::vector<std::thread> threads;
for(int i=0;i<10000;i++){
	threads.emplace_back(std::thread(task));
}
```
- 但是这样创建线程会有一些问题:
	1. 创建线程本身有开销,一直循环开销很大
	2. 线程太多会导致系统调度压力大,要同时统筹所有线程
	3. 线程数量不可控,可能大于CPU承受能力
	4. 每次任务来的时候循环创建线程,任务结束又销毁,性能太低
- 针对这些问题,提出线程池模型:
	- **提前创建一批线程,让它们一直等待任务,任务来了就从任务队列中取任务并执行,没有任务就保持休眠**
	- 所以线程池本质上就是一堆等待任务的子线程,是典型的==生产者-消费者==模型

## 2.线程池的基本模型
- **ThreadPool**
	- worker thread 1
	- worker thread 2
	- worker thread 3
	- task_queue
每个工作线程都在重复一件事情:
```text
while(线程池没有关闭){
	等待任务;
	从任务队列中取任务;
	执行任务；
}
```
==这就是线程的工作循环 workloop==

## 3.构建简单的线程池
- 一个简单的线程池需要哪些东西?
	1. 首先需要有许多工作线程
	2. 然后有每个线程的循环工作函数(==这个其实可以自己构建,本版本基于高程OJ==)
	3. 任务队列
	4. 互斥锁来保护(这里还没有理解互斥锁在保护什么)
	5. 线程池是否停止运行标签
我们可以开始构建线程池:
```cpp
#include<iostream>
#include<vector>
#include<mutex>
#include<thread>
#include<queue>

struct Task{
	void (*function)(void*);
	void* arg;
};
class TaskQueue{
private:
	std::queue<Task> tasks;
	std::mutex mtx;

public:
	TaskQueue();
	~TaskQueue();
	
	void push(Task task);
	bool pop(Task& task);
	
	int size();
	bool empty();
};

class ThreadPool{
private:
	TaskQueue task_queue;
	std::vector<std::thread> workers;
	std::mutex stop_mtx;
	bool stopped;
	bool joined;
	static void workLoop(ThreadPool* pool);
	
public:
	ThreadPool(int thread_count);
	~ThreadPool();
	
	void addTask(Task task);
	void wait();
};
```

### 3.1 结构拆分
#### 3.11 Task
"任务"往往指一个函数,所以任务队列的任务就是一个类似回调函数的设计,在需要的时候再调用:
> [[程序设计中回调函数的设计]]

调用的时候就是`task.function(task.arg);`
#### 3.12 TaskQueue
- 这是一个受到锁保护的任务队列
- 一个任务队列可能同时有线程在取任务,有线程在塞任务,不加锁就会导致数据竞争
```cpp
void TaskQueue::push(Task task){
	std::lock_guard<std::mutex> lock(mtx);
	tasks.push(task);
}
```
`pop()`的实现复杂一点，但也很经典：
```cpp
bool TaskQueue::pop(Task& task){
	std::lock_guard<std::mutex> lock(mtx);
	if(!tasks.empty()){
		task=tasks.front();
		task.pop();
		return true;
	}
	return false;
}
```
这是C++里经典的通过bool来判断有没有取成功，然后用引用把取到的任务带出来

#### 3.13 线程池本体ThreadPool
- 线程池的本体大概可以分为几个部分：
	1. 雇佣工人，也就是创建子线程，在构造函数里完成
	2. 往队列里塞任务，等待子线程取，即`addTask()`
	3. 子线程工作函数，一直进行尝试取任务->取到了执行/没取到继续尝试直到停止工作信号循环
	4. 线程池关闭函数，等待所有子线程跑完就结束线程池，即`wait()`
一个一个看具体实现:
**构造函数：创建多个子线程**
```cpp
ThreadPool::ThreadPool(int thread_count){
	stopped=false;
	joined=false;
	if(thread_count<=0){
		workers.emplace_back(std::thread(workLoop,this));
		return;
	}
	for(int i=0;i<thread_count;i++){
		workers.emplace_back(std::thread(workLoop,this));
	}
}
```
很好理解，创建`thread_count`个子线程一起工作，`stopped`表示是否停止接收新任务，`joined`表示是否回收过线程，主要是防止`wait()`和析构函数同时join
`addTask`塞任务：
```cpp
void ThreadPool::addTask(Task task){
	std::lock_guard<std::mutex> lock(stop_mtx);
	if(!stopped){
		task_queue.push(task);
	}
}
```
`workLoop`最核心的工作循环:
```cpp
void ThreadPool::workLoop(ThreadPool* pool){
	while(true){
		Task task;
		if(task_queue.pop(task)){
			task.function(task.arg);
		}
		else{ //这里没取到说明队列为空
			if(pool->isStopped()){
				break; //线程池停止工作，工人一个个退出循环
			}
		}
	}
	std::this_thread::yield();
}
```
`wait()`让线程池停止工作：
```cpp
void ThreadPool::wait(){
	{
		std::lock_guard<std::mutex> lock(stop_mtx);
		if(joined){
			return;
		}
		stopped=true;
		joined=true;
	}
	for(auto& worker:workers){
		if(worker.joinable()){
			worker.join();
		}
	}
}
```
这里修改joined是防止调用析构函数的时候二次join，然后有一个内层`{}`作用域，其作用是把锁的作用域缩小到“改标志位”那一小段，这样在做耗时的`join()`的时候就不会一直占着锁
