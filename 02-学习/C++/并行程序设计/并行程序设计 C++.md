## 本节最重要的结论

### 核心认识
- 并行程序的背景，是单核性能增长放缓，需要借助多核提升程序效率。
- 并发不等于并行：并发强调“多个任务交替推进”，并行强调“多个任务同时执行”。
- 线程是 C++ 并发编程的基础执行单元，但线程一旦共享数据，就会带来正确性问题。

### 当前入门先掌握什么
- 先建立主线：[[为什么需要并行程序]] → [[并发与并行]] → [[进程与线程]] → [[std-thread和this_thread|C++ std::thread]]。
- 重点理解为什么共享数据会出错：[[数据竞争与临界区]]。
- 先掌握最基础的保护方式：[[互斥锁 mutex]] 和 [[std-lock-guard|std::lock_guard]]。

### 学习这部分时要记住
- 像 `sum += sqrt(i)` 这样的语句通常不是原子的，多个线程同时执行可能产生错误结果。
- 互斥锁的作用是保护临界区，避免多个线程同时修改共享数据。
- `std::lock_guard` 比手动 `lock()` / `unlock()` 更安全，更符合 C++ 的 RAII 风格。

## 建议学习顺序 / 学完标志

### 建议学习顺序
1. 先看 [[为什么需要并行程序]]，搞清楚为什么现代程序必须考虑多核与并行。
2. 再看 [[并发与并行]]，分清两个概念，避免后面把术语混用。
3. 接着看 [[进程与线程]]，理解线程为什么会成为并发编程的核心单位。
4. 然后学习 [[std-thread和this_thread|C++ std::thread]] 和 [[join 和 detach]]，先学会最基本的线程创建、启动和回收。
5. 再学习 [[数据竞争与临界区]]，真正理解“为什么多线程程序会出错”。
6. 最后学习 [[互斥锁 mutex]] 和 [[std-lock-guard|std::lock_guard]]，掌握最基础的共享数据保护方法。

### 学完这一阶段的标志
- 你能用自己的话解释“并发”和“并行”的区别。
- 你能解释进程和线程的关系，并说明为什么线程更容易出现共享数据问题。
- 你能写出最基本的 `std::thread` 示例，并知道什么时候需要 `join()`。
- 你能说明 `detach()` 的基本含义，并知道它不能随便用。
- 你能看懂一个简单的数据竞争例子，并解释它为什么会产生错误结果。
- 你能使用 `mutex` 和 `lock_guard` 改写一个简单的共享变量案例。
- 你已经建立起“先保证正确，再考虑性能”的基本并行编程意识。
