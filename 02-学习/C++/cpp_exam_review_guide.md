> 本文基于课程 PPT 课件与《重要考点》整理。其中标红考点为**最重要**（高概率出题），黑色考点为**次要**（覆盖即可）。结合三种题型——**程序分析题、程序纠错题、手写代码题**——给出复习路线、出题预测与最可能被改编的代码片段。

## 一、考试结构与三大题型拆解

| 题型 | 给你什么 | 要你做什么 | 备考核心能力 |
|------|----------|------------|--------------|
| **程序分析题** | 一段代码 | 分析其作用 / 预测输出 | 准确"在脑中跑程序"：构造/析构/拷贝/赋值的调用顺序，静态 vs 动态绑定，引用计数变化 |
| **程序纠错题** | 一段有目标说明的代码 + 若干错误 | 找出全部错误并说明 | 熟记"标准正确写法"，对照差异定位错误（深浅拷贝、`delete[]`、虚析构、`const`、`release/reset` 等） |
| **手写代码题**（篇幅不短） | 一个功能目标 | 完整写出类/函数 | 默写出 String 类、Stack 类、智能指针、RAII 包装、操作符重载、模板等"模板化"代码 |

**关键判断**：三种题型的素材**几乎全部来自 PPT 现有代码的改编**。改编手法通常是：
- 把"正确版"挖空 / 改错（→ 纠错题、填空式分析题）
- 把"示意省略（`......`）"补全（→ 手写题）
- 把"分析过程注释"删掉，让你重新推导（→ 分析题，尤其是构造/析构/虚函数调用链）
- 把单一类换一个业务外壳（如 `String`→`MyArray`、`Complex`→`Fraction`、`Counter`→`Timer`），骨架不变

### 模块 1：拷贝构造与深浅拷贝 🔴🔴🔴（出题概率最高）

**核心知识点**
- 拷贝构造函数三种触发场景：用同类对象初始化、对象作值参数传入、对象作返回值。
- 隐式拷贝构造 = 逐成员拷贝（成员对象递归调用其拷贝构造）。
- 含裸指针 + 自申请资源的类 → 必须自定义深拷贝，否则：悬垂、重复释放、互相干扰。
- 自定义拷贝构造**默认调用成员对象/基类的默认构造**，要深拷贝成员对象须在初始化表写 `: a(b.a)`。
- 初始化（`A b=a;` / `B b2(b1)`）调拷贝构造；赋值（`b=a;`）调 `operator=`。

**最可能被改编的代码（源自 3-1 拷贝构造、2-3 析构、6-2 赋值）**
```cpp
class String {
    int len; char *str;
public:
    String(const char *s){ len=strlen(s); str=new char[len+1]; strcpy(str,s); }
    String(const String& s){ len=s.len; str=new char[len+1]; strcpy(str,s.str); } // 深拷贝
    String& operator=(const String& s){
        if(&s==this) return *this;        // 防自赋值
        delete []str;
        str=new char[s.len+1]; strcpy(str,s.str); len=s.len;
        return *this;
    }
    ~String(){ delete []str; len=0; str=NULL; }
};
```

**出题预测**
- **分析题**：给 `String s1("abcd"); String s2(s1);` 问「使用隐式拷贝构造会发生什么问题」（答：浅拷贝、两指针指向同一块、析构二次释放、互相干扰）。或给出有/无 `: a(b.a)` 两版本，问 `b2.a.x` 的值。
- **纠错题**：给一个 String 类，故意（1）漏掉拷贝构造（→只有浅拷贝）（2）`operator=` 漏掉自赋值检查 / 漏 `delete[]str` / 漏返回 `*this`（3）`new char[len]` 少分配 `+1`。要你找出。
- **手写题**：「为下列含裸指针的类补全：拷贝构造、赋值操作符、析构函数，实现深拷贝」——把 `String` 换皮成 `Buffer`/`DynArray`，骨架完全一致。

### 模块 2：构造/析构调用顺序 🔴🔴🔴

**核心知识点**
- 成员对象：先成员对象构造（按声明顺序）→ 本类构造体；析构相反。
- 继承 + 成员对象：构造 `基类 → 成员对象 → 派生类(B→M→D)`；析构 `D→M→B`。
- 成员初始化顺序只看**声明顺序**，与初始化表书写顺序无关。
- 就地初始化 → 初始化列表 → 构造函数体。
- 调用非默认构造须写在初始化表：`B(int i,int j): a(j) {...}` / `B(int i,int j):A(i){...}`。

**最可能被改编的代码（源自 2-3 Slide14、4-1 Slide28、4-1 Slide33）**
```cpp
class A { int x; public: A(){x=0;} A(int i){x=i;} };
class B { A a; int y; public:
    B(){y=0;} B(int i){y=i;} B(int i,int j):a(j){y=i;} };
// B b2(1,2); → 调 B(int,int) 与 A(int)：b2.y=1, b2.a.x=2
```

**出题预测**
- **分析题**（极高频）：在 A、B（或加第三层 C）的构造/析构里各加一句 `cout`，问「创建并销毁对象后输出顺序」。务必能写出完整 cout 序列。
- **纠错题**：把非默认基类构造写在函数体内而非初始化表（导致先调默认构造再赋值）；或 `const`/引用成员未在初始化表初始化。
- **手写题**：「设计 D 继承 B，且含成员对象 M，写出能正确传递参数到各基类/成员的构造函数」。

### 模块 3：虚函数与静态/动态绑定 🔴🔴🔴

**核心知识点**
- 默认静态绑定；只有**通过指针或引用**调用**虚函数**才动态绑定。
- 派生类同型构函数自动是虚函数（`virtual` 可省）。
- **构造/析构函数中调用虚函数 → 不动态绑定**（绑到当前类）。
- 析构函数应设为虚函数，否则 `delete 基类指针` 不调用派生类析构（内存泄漏）。
- 非虚函数即使同名也静态绑定；基类指针访问派生类新成员需 `dynamic_cast`。

**最可能被改编的代码（源自 5-1 Slide12~15 —— 本课"分析题之王"）**
```cpp
class A { public:
    A(){ f(); }            // 构造中调 f → 静态绑定到 A::f
    virtual ~A(){ f(); }   // 析构中调 f → 静态绑定到 A::f
    virtual void f();
    void g();
    void h(){ f(); g(); }
};
class B: public A { public:
    void f(); void g();
};
// A *p=new B;  → 构造时调 A::A() 与 A::f
// p->f();      → B::f（虚，动态）
// p->g();      → A::g（非虚，静态）
// p->h();      → A::h, B::f, A::g
// delete p;    → 若 ~A 非虚，只调 A::~A 与 A::f（泄漏 B）
```

**出题预测**
- **分析题**：给一组 `A a; B b; A* p; p=&a/&b;` 后的若干 `p->f()/g()/h()`，逐行问调用哪个函数。这是几乎必考的分析题，**把 5-1 第12~15页背到能复述**。
- **纠错题**：目标"通过基类指针正确销毁派生类对象"，错误处是 `~A()` 未加 `virtual` → 让你指出并说明后果。
- **手写题**：用抽象类 `Figure`（5-2）实现多态图形，写出 `draw()` 动态绑定的高层循环代码 `for(...) figures[i]->draw();`。

### 模块 4：派生类的初始化/消亡/拷贝/赋值 🔴🔴

**核心知识点**
- 派生类隐式拷贝构造会调基类拷贝构造；自定义拷贝构造默认调基类**默认**构造，需 `:A(b)` 显式调基类拷贝构造。
- 自定义 `operator=` 不会自动调基类赋值，须显式：`*(A*)this=b;` 或 `this->A::operator=(b);`，并先做自赋值检查。

**最可能被改编的代码（源自 4-1 Slide35、Slide37）**
```cpp
class B: public A { public:
    B(const B& b):A(b) { /* 初始化派生成员 */ }     // 显式调基类拷贝构造
    B& operator=(const B& b){
        if(&b==this) return *this;
        *(A*)this = b;                              // 调基类赋值
        /* 派生成员赋值 */
        return *this;
    }
};
```

**出题预测**
- **纠错题**：自定义拷贝构造漏写 `:A(b)`（基类部分被默认构造，数据丢失）；`operator=` 漏 `*(A*)this=b`。
- **分析题**：问"派生类隐式拷贝构造 vs 自定义拷贝构造在基类部分行为差异"。

### 模块 5：`new`/`delete` 操作符重载 🔴🔴

**核心知识点**
- `new` 两功能：分配空间 + 调构造；`delete` 两功能：调析构 + 释放空间。重载只改"分配/释放"，不影响构造/析构调用。
- `void* operator new(size_t size)`（必须 static，返回 `void*`）；`void operator delete(void* p)`。
- 带额外参数的定位 new：`void* operator new(size_t, void* p){return p;}`，用法 `new(buf) A(1,2)`，需手动 `p->~A()`。
- 自由空间链表（NUM 块、`p_free`、`next`）提升效率。
- `new[]`/`delete[]`：有析构函数时 size 会多 4 字节存元素个数；`delete[]` 的 `[]` 不能漏。

**最可能被改编的代码（源自 6-2 Slide13、16、18、22~23）**
```cpp
class A { int x,y;
  A* next; static A* p_free;
public:
  static void* operator new(size_t size){
      if(p_free==NULL){
          p_free=(A*)malloc(size*NUM);
          for(int i=0;i<NUM-1;i++) p_free[i].next=&p_free[i+1];
          p_free[NUM-1].next=NULL;
      }
      A* p=p_free; p_free=p_free->next; memset(p,0,size); return p;
  }
  static void operator delete(void* p){
      ((A*)p)->next=p_free; p_free=(A*)p;
  }
};
A* A::p_free=NULL;
```

**出题预测**
- **分析题**：给定位 new 例子，问 `new(buf) A(1,2)` 把对象建在哪、为何不能用系统 `delete`、`p->~A()` 的作用。
- **纠错题**：`operator new` 返回类型写成 `void` / 漏 static / `delete` 释放后未维护链表。
- **手写题**：「重载 `new/delete`，把动态对象初始化为全 0」或「用自由空间链表管理某类对象」——直接默写上面骨架。

### 模块 6：异常处理 🔴🔴

**核心知识点**
- `try{...}` 包住可能出错代码；`throw 表达式` 抛任意类型对象（void 除外）；`catch(类型 变量){...}` 按**类型精确匹配**捕获。
- throw 后其后语句不再执行，沿**函数调用链**退栈查找匹配 catch。
- 一个 try 可跟多个 catch；嵌套 try：内层无匹配则向外层找；全链无匹配 → `terminate()`→`abort()`。

**最可能被改编的代码（源自 7-2 Slide20、23、24）**
```cpp
void f(){ throw 1; /*或*/ throw 1.0; /*或*/ throw "abcd"; }
int g(){
    try { f(); }
    catch(int)    { /*处理 throw 1*/ }
    catch(double) { /*处理 throw 1.0*/ }
    catch(char*)  { /*处理 throw "abcd"*/ }
}
int divide(int x,int y){ if(y==0) throw 0; return x/y; }
```

**出题预测**
- **分析题**（高频）：给嵌套 `f/g/h` 各带不同 catch（7-2 Slide23），问"在 h 中 `throw X` 由哪个函数的哪个 catch 捕获"。务必能追踪 `throw 1`（被 g 捕获）、`throw "abcd"`（被 f 捕获）等。
- **纠错题**：catch 顺序/类型不匹配（如抛 `int` 却只有 `catch(double)`）；throw 后还写"善后"代码。
- **手写题**：「写一个除零异常处理程序，做到不终止直到输入正确为止」（循环 + try/catch）。

### 模块 7：内存安全 + RAII + 智能指针 🔴🔴🔴

**核心知识点**
- 时间类问题：use-after-free、double free、悬垂指针、内存泄漏；空间类：缓冲区溢出、空指针解引用、未初始化访问。
- **RAII**：构造获取资源、析构释放资源（`FileObj` 例）。
- `unique_ptr`：独占所有权，**禁止拷贝/赋值**（编译错），靠 `std::move` / `release()` / `reset()` 转移。
- `shared_ptr`：引用计数，拷贝/赋值 +1，析构 -1，归零销毁；**用同一裸指针构造两个 shared_ptr → double free**；**循环引用 → 内存泄漏**。
- `weak_ptr`：不增加引用计数，打破循环引用；`lock()` 升级为 shared_ptr，`expired()`、`use_count()`。

**最可能被改编的代码（源自 10 Slide15、20、26、31~32、36~40）**
```cpp
// Toy 智能指针（手写题常客）
template<typename T> class ToyPtr {
public:
    explicit ToyPtr(T* p):ptr_(p){}
    ~ToyPtr(){ delete ptr_; }
    T& operator*(){ return *ptr_; }
    T* operator->(){ return ptr_; }
private:
    T* ptr_;
};

// shared_ptr 引用计数推导（分析题常客）
shared_ptr<int> x(new int(10));   // ref=1
{ shared_ptr<int> y=x;            // ref=2
  auto z(y); }                    // ref=3 → 出作用域 y,z 销毁，ref=1
// 结束 ref=0
```

**出题预测**
- **分析题**（极高频）：给一段 shared_ptr 嵌套作用域代码，逐行标注**引用计数变化**，并指出最终是否释放。或 weak_ptr 的 `lock()` 后输出。
- **纠错题**（极高频）：① `unique_ptr<int> y(x);` / `z=x;`（拷贝/赋值被禁，要改 `std::move`）；② 用同一裸指针 `p` 构造两个 `shared_ptr`（double free）；③ 双向链表用两个 `shared_ptr` 造成循环引用（应把一端改 `weak_ptr`）。
- **手写题**：① 默写 `ToyPtr` 模板；② 用 RAII 写一个文件/锁/内存的资源包装类（构造获取、析构释放）；③ 把裸指针版改写为智能指针版以消除泄漏。

### 模块 8：聚合与组合 🔴

**核心知识点**
- 聚合（aggregation）：部分可独立存在，成员用**指针**，外部创建后传入，析构**不删**成员。
- 组合（composition）：部分随整体生灭，成员是**对象**或内部 `new`/`delete` 的指针。
- 继承 vs 组合：继承易得子类型、向外暴露 `public+protected`；组合只暴露 `public`，无子类型关系。`private` 继承≈组合。

**最可能被改编的代码（源自 4-3 Slide5、11、13、14）**
```cpp
class B { A* pm; public:                 // 聚合
    B(A* p){ pm=p; } ~B(){ pm=NULL; } };
class C { A* pm; public:                 // 组合
    C(){ pm=new A; } ~C(){ delete pm; } };
```

**出题预测**
- **分析题/概念题**：判断给定两类是聚合还是组合，说明成员对象何时创建/销毁。
- **纠错题**：组合类析构漏 `delete pm`（泄漏）；或聚合类析构里 `delete pm`（误删外部对象）。
- **手写题**：用组合（持有 `LinearList`）实现 `Queue` 的 `en_queue/de_queue`（4-3 Slide13）。

### 模块 9：并行程序设计 🔴

**核心知识点**
- `std::thread t(func, args...)` 创建即运行；`join()` 阻塞等待子线程，`detach()` 放弃控制权。
- 数据竞争：多线程同时访问共享数据且至少一个写；临界区需保护。
- `std::mutex` + `lock()/unlock()`；`std::lock_guard` 构造加锁、析构解锁（RAII 思想，**与模块 7 呼应**）。
- 经典 bug：多个线程 `sum += x` 未加锁导致结果不确定（PPT Slide27 的交错执行图）。

**出题预测**
- **分析题**：给未加锁的累加多线程代码，问"为什么结果不确定"（数据竞争 + 读改写非原子）。
- **纠错题**：忘记 `join()`（主线程退出资源销毁，子线程悬空）；临界区未加锁。
- **手写题**：用 `std::thread` + `lock_guard`（或 mutex）写一个线程安全的累加/区间平方根求和程序。

> 注：并行章节多数代码以图片形式在 PPT 中，建议结合 `std::thread`/`mutex`/`lock_guard` 标准用法记忆。

### 模块 10：访问控制与子类型 🔴

**核心知识点**
- `public/protected/private` 成员的可见域；`protected` 缓解封装与继承矛盾。
- 继承方式 × 基类访问控制 → 派生类对外访问控制（记住那张表）。
- 子类型：`public` 派生类对象可赋给基类、可传给需基类的函数、基类指针可指向派生类对象（反向不行）。

**出题预测（多为纠错/判断）**
- **纠错题**：派生类直接访问基类 `private` 成员；`B *q=&a;`（基类对象赋给派生类指针，非法）；`b=a;`（基类赋给派生类，非法）。
- **分析题**：给定继承方式，逐行判断 `f()/g()/h()` 在派生类内、派生类外是否可访问（4-1 Slide21）。

### ⚫ 第二梯队速记（用于纠错/小题/概念题）

## 四、高频"陷阱"清单（纠错题命中率最高）

1. 含裸指针的类只写析构、**漏拷贝构造或漏赋值** → 浅拷贝灾难。
2. `operator=` **漏自赋值检查**、漏 `delete[]`、漏 `return *this`。
3. `new char[len]` **少 `+1`**（没给 `'\0'` 留位）。
4. 基类析构函数**未加 `virtual`** → `delete 基类指针` 泄漏派生部分。
5. 自定义派生类拷贝构造/赋值**漏调基类**（`:A(b)` / `*(A*)this=b`）。
6. **构造/析构里调虚函数**误以为会动态绑定。
7. `unique_ptr` 被**拷贝/赋值**（应 `std::move`）。
8. 同一裸指针构造**两个 shared_ptr**（double free）；**循环引用**未用 weak_ptr。
9. `delete[]` 写成 `delete`；组合类析构**漏 `delete`**；聚合类析构**误 `delete`**。
10. 成员初始化顺序按**声明顺序**而非初始化表顺序（`const`/引用成员必须初始化表初始化）。
11. catch **类型不匹配**或顺序不当；throw 后写多余代码。
12. 多线程**忘 `join`** / 临界区**未加锁**。
13. 模板实现放 `.cpp` 导致**链接错误**（应放 `.h`）。
