# 链表

## 1. 基本概念

- 链表是线性表的链式存储实现，节点之间通过指针相连
- 与顺序表（数组）相对：顺序表随机访问 O(1)、插入删除 O(n)；链表随机访问 O(n)、头尾插入删除 O(1)
- 单链表成员：`head_`（头指针）、`tail_`（尾指针）、`size_`（节点数）
- 节点结构：`value` + `next`

```cpp
struct Node {
    T value;
    Node* next;
    Node(T v) : value(v), next(nullptr) {}
};
```

## 2. 接口

继承自 `LinearList<T>`，与顺序表共享同一套抽象接口：

```text
size() / empty() / at() / set() / insert() / erase() / find()
```

单链表扩展：`push_front()`、`push_back()`、`clear()`、`reverse()`。

### 表示不变量

```text
空表：  head_ == nullptr && tail_ == nullptr && size_ == 0
非空表：tail_->next == nullptr
任意：  从 head_ 沿 next 恰好走过 size_ 个节点
```

## 3. 错误点复盘

> 本节记录 2026-08 实现单链表时实际犯过的错误，按类别整理。链表的坑集中在**指针操作**与**边界情况**，几乎每个错误都源于"想当然"而非"画图验证"。

### 3.1 编译类

| # | 错误 | 现象 | 原因与教训 |
|---|------|------|-----------|
| 1 | `head` 写成 `head_` | 析构、`at()`、`clear()` 编译失败 | 成员变量命名要统一；编译器提示 `did you mean 'head_'?` 时，先全局自查一遍再编译 |

### 3.2 指针断链 / 内存类

| # | 错误 | 现象 | 原因与教训 |
|---|------|------|-----------|
| 2 | 空表头插重复 `new` | 第一个 `newNode` 无人持有，内存泄漏 | 先 `new Node(value)` 又 `new Node(value)`；空表应**直接复用**已建节点 |
| 3 | 非空表头插接错指针 | 原头结点脱链，元素丢失 | 写成 `newNode->next = head_->next`；正确是 `newNode->next = head_; head_ = newNode;`——**画图**再改指针 |
| 4 | 尾删后 `tail_->next` 未置空 | 新尾节点仍指向已释放内存，遍历/析构 use-after-free | 删尾后必须 `tail_->next = nullptr;` |
| 5 | 删唯一节点后 `tail_` 悬垂 | `tail_` 指向已 delete 的节点 | 单节点删除后必须 `head_ = tail_ = nullptr`；注意 `if (size_ = 0)` 是**赋值**恒为 false，要写 `==` |

### 3.3 作用域类

| # | 错误 | 现象 | 原因与教训 |
|---|------|------|-----------|
| 6 | `erase()` 的 `value` 定义在分支内 | `return value` 报"未声明" | `{}` 内局部变量出块即消失；返回值应**在函数开头声明**，分支里只赋值 |
| 7 | `erase()` 声明返回 `T` 却无 `return` | 未定义行为 | 接口契约必须兑现：先保存被删元素，再 `return` |

### 3.4 复制 / 赋值类

| # | 错误 | 现象 | 原因与教训 |
|---|------|------|-----------|
| 8 | 拷贝构造空表解引用 `other.head_->value` | 空表复制崩溃 | 复制前先判空表 |
| 9 | 拷贝构造后 `tail_` 未赋值 | 复制后 `push_back` 访问未初始化指针 | 复制完要让 `tail_` 指向末节点并断链 |
| 10 | 移动赋值缺 `return *this` | 未定义行为（模板未实例化时编译器不报） | 返回引用的函数必须有 return；用 `-fsyntax-only` 只能查语法，**实例化才能查控制流** |
| 11 | `operator=` 中写 `SinglyLinkedList(other);` | 编译报 shadow 参数 | **most vexing parse**：`类型(名字);` 永远按"声明变量"解析，不是构造调用；用 `类型{名字}` 或命名变量 |

> **most vexing parse 详解**（本次最大的认知收获）：
>
> ```cpp
> Foo(other);   // 意图：拷贝构造临时对象
>               // 实际：声明变量 Foo other;（调用默认构造）
> ```
>
> 三条规则各管一段：
> 1. **注入类名**：类内定义成员函数时可写 `类名`（省略 `<T>`），类内 `类名` 等价 `类名<T>`
> 2. **模板名不是类型**：类外提到类模板必须写 `类名<T>`
> 3. **声明优先**：函数体内 `类型(标识符);` 一律按声明解析，与是否模板无关
>
> 验证：`Foo(other)` 运行时实际调用**默认构造**；`Foo{other}` 才是拷贝构造。

### 3.5 设计类（做得好的，值得记住）

| # | 做法 | 价值 |
|---|------|------|
| 12 | 抽出 `copy_from()` 私有辅助 | 拷贝构造与复制赋值共用一份逻辑，避免两份重复代码改一处漏一处 |

## 4. 通用检查清单（每次写链表后自查）

```text
□ 所有成员变量名一致（head_ / tail_ / size_）
□ insert：空表复用新节点；头插接住原 head_ 本身
□ erase：返回值在函数开头声明；删唯一节点后头尾都置空；尾删后新 tail_->next == nullptr
□ 比较用 ==，赋值用 =（尤其 if 里）
□ 复制构造：判空表；复制完 tail_ 指向末节点
□ 赋值运算符：自赋值保护 + return *this
□ 临时对象用 类型{...} 或命名变量，不用 类型(名字);
□ 每个分支结束后检查不变量：size_ 与实际节点数一致
```

## 5. 复杂度对照

| 操作 | 顺序表 ArrayList | 单链表 SinglyLinkedList |
|------|-----------------|------------------------|
| `at(i)` / `set(i,x)` | O(1) | O(n) |
| 头插 / 头删 | O(n) | O(1) |
| 尾插（有 tail_） | 均摊 O(1) | O(1) |
| 中间插删 | O(n) | O(n) |
| `find(x)` | O(n) | O(n) |
| `reverse()` | O(n) | O(n) |
